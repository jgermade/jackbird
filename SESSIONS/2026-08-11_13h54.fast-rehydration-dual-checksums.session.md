# Session: Fast Metadata Re-hydration, Dual Checksums & Background Verifier Queue

**Date**: 2026-08-11 13:54
**Summary**: Fast workspace startup on page reload, dual checksum tracking (`fullChecksum` vs `audioChecksum`), and non-blocking background verification queue.

## Problem Statement

When reloading the page with an open workspace containing hundreds of tracks (e.g. 739 MP3s), the application displays `Cargando metadatos 603/739...` and takes several seconds.

Even though metadata is saved in `.meta/mp3-manager.json`, the startup process currently re-reads all MP3 file bytes from disk and re-calculates full SHA-1 hashes to verify cache validity.

## Goals

1. **Fast Re-hydration**: Use file size (`size`) and last modified timestamp (`lastModified`) to validate cached metadata instantly on reload (reducing startup time from seconds to milliseconds for unchanged files).
2. **Dual Checksums**:
   - `fullChecksum`: Hash of entire file bytes (changes when tags or artwork change).
   - `audioChecksum`: Hash of the raw MP3 audio payload (excluding ID3v2 headers and ID3v1/APE footers). Preserves track audio identity across retagging.
3. **Background Verification Queue**:
   - Track `lastVerifiedAt` timestamp per file.
   - Run a low-priority, non-blocking background queue that incrementally verifies files (reading bytes and recalculating dual hashes) without blocking UI or audio playback.

## Implementation Plan

1. **Schema Updates (`src/types.ts` & `src/views/Mp3ManagerView.tsx`)**:
   - Extend `MetaRecord` to include `fullChecksum`, `audioChecksum`, `size`, `lastModified`, `lastVerifiedAt`. Maintain backward compatibility with legacy `checksum` field.
   - Extend `Mp3Track` type in `src/types.ts` with optional `fullChecksum`, `audioChecksum`, `lastVerifiedAt`, `lastModified`.

2. **Audio Payload Extractor & Dual Checksum Helper (`src/lib/id3.ts`)**:
   - Create `getAudioFrameSlice(bytes: Uint8Array): Uint8Array` to skip ID3v2 header at offset 0 and trim ID3v1 / APEtag at EOF.
   - Create `calculateDualChecksums(bytes: Uint8Array): Promise<{ fullChecksum: string; audioChecksum: string }>` using SHA-1.

3. **Fast Re-hydration in `Mp3ManagerView.tsx`**:
   - Compare `file.size` and `file.lastModified` against stored `snapshot.tracks[relativePath]`.
   - If both match, immediately load `metadata`, `fullChecksum`, `audioChecksum`, `lastVerifiedAt` into state.
   - If mismatched or missing, enqueue for full byte reading and ID3 parsing.

4. **Background Verification Worker (`Mp3ManagerView.tsx`)**:
   - Add a background verification loop that processes unverified or oldest-verified tracks during browser idle time (`requestIdleCallback` or throttled `setTimeout`).
   - Update `MetaSnapshot` and periodically flush to `.meta/mp3-manager.json`.

## Extension (2026-08-11 14:45) — Snapshot-First Rehydration (Instant Restore)

### Problem

Al restaurar sesión, `hydrateRoot` hace primero un walk completo del filesystem (`vfs.listFiles`) y solo después lee el snapshot. Esto hace que el mensaje "Restaurando tabs..." persista durante el tiempo que tarda el walk, aunque el 100% de los tracks estén en caché.

### Goal

Leer el snapshot **primero**, mostrar los tracks en pantalla instantáneamente desde el caché, quitar el mensaje "Restaurando tabs...", y luego hacer el walk del filesystem **en background** para detectar archivos nuevos, eliminados o modificados.

### Implementation Plan

1. **`hydrateRoot` refactorizado (2 fases)**:

   **Fase 1 — Sincronización desde snapshot (inmediata):**
   - Leer `readMetaSnapshot(vfs)` → JSON de metadatos.
   - Construir la lista `initialTracks` directamente a partir de las entradas del snapshot (sin walk del FS).
   - Llamar a `setRoots(...)` para añadir el root al estado con todos los tracks del snapshot.
   - Retornar inmediatamente → `restoring` pasa a `false`, el mensaje desaparece.

   **Fase 2 — Walk del filesystem (background):**
   - Hacer `vfs.listFiles({ extensions: [".mp3"] })` en background tras el primer render.
   - Comparar con los tracks del snapshot:
     - **Nuevos o modificados** (`size`/`lastModified` no coincide): encolar para lectura de bytes + reparse de ID3.
     - **Eliminados**: marcar o eliminar del estado.
     - **Sin cambios**: actualizar `lastVerifiedAt` si no lo tenían.
   - Actualizar el estado de forma incremental y guardar el snapshot.

2. **`restoreSession` en el `useEffect` inicial**:
   - Esperar solo la Fase 1 de `hydrateRoot` antes de llamar `setRestoring(false)`.
   - La Fase 2 corre de forma transparente en background.

3. **Indicador de sincronización en background**:
   - Reutilizar el flag `loadingMetadata` que ya existe para mostrar el estado del walk en background (ya visible en la UI como "Cargando metadatos X/Y...").
