# Session: File Explorer UI Refresh

**Date**: 2026-08-11 19:09
**Summary**: Redesign the library file-tree explorer (`TrackWizardList` + `.library-pane`) for clearer hierarchy, denser readability, theme-aware colors, and interaction closer to a real file browser.

## Problem Statement

The wizard tree works functionally but feels like a prototype:

1. **Emoji chrome** (`📁`, `💿`, `▾`/`▸`, `🧩`) looks inconsistent with the rest of the app (Space Grotesk / IBM Plex).
2. **Hardcoded light-only colors** in tree/track rows (`#f2f7ff`, `#e9f1ff`, `#355dcb`, `#5f8e66`) ignore CSS variables and break dark theme.
3. **Awkward expand UX**: caret and folder label are two separate click targets; most file explorers toggle expand on the whole row (or caret only) with clearer hit areas.
4. **Weak hierarchy**: albums, discs, and tracks share similar weight; no depth guides; track titles are blue link-colored (`#355dcb`) instead of reading as list content.
5. **Sparse header**: "Library" + count only — no filter, no expand/collapse all, no empty/loading polish inside the list itself.
6. **Always-visible consolidate control** steals horizontal space and noise on every track row.

## Goals

1. Make the left pane read as a proper **file explorer**: clear folders vs tracks, denser rows, readable truncation, strong selected/active states.
2. Stay inside the existing design system (CSS variables, IBM Plex / Space Grotesk, no new deps).
3. Improve dark theme parity for all tree styles.
4. Keep behavior (selection, Shift-range, album/disc expand, consolidate action) unchanged unless noted below.
5. CSS-first refresh with light markup tweaks in `TrackWizardList.tsx`; avoid rewriting tree-building logic in `Mp3ManagerView.tsx` unless needed for counts / expand-all.

## Design Direction

Visual references: Finder sidebar / VS Code explorer — not a music "playlist" look.

- Neutral ink for track titles; muted secondary for artist.
- Folders slightly heavier weight; discs more muted / smaller.
- SVG (inline) or CSS shapes for caret + folder/track glyphs instead of emoji.
- Optional subtle vertical depth guides via left border / inset shadow using `depth`.
- Selection: accent-soft fill + left accent bar (already familiar from detail pane language).
- Hover: soft surface tint via variables only.

## Implementation Plan

### 1. Library pane chrome (`src/styles.css`, small markup in `Mp3ManagerView.tsx` / `TrackWizardList.tsx`)

- Restyle `.library-pane` / `.library-head` to use `var(--chrome)` / `var(--panel)` consistently (drop hardcoded `#fefefe`).
- Header layout:
  - Title + track count (keep).
  - Compact actions: **Expand all** / **Collapse all** (wire to existing `expandedAlbums` / disc expand sets in the view).
- Optional thin search/filter input under the header filtering visible rows by folder/track label (client-side only on already-built `treeRows`). If too much scope for this pass, ship expand/collapse first and leave filter as follow-up.

### 2. Tree row interaction (`TrackWizardList.tsx`)

- Single row surface for album/disc:
  - Caret button remains for a11y (`aria-expanded`).
  - Clicking the folder label also toggles expand **and** selects the row (current `onSelectRow` behavior preserved; toggle on caret; label click = select + optional expand-if-collapsed — propose: **label selects; caret toggles**; double-click label toggles — document exact behavior in walkthrough after approval).
- Track rows:
  - Replace emoji with a small disc/note glyph (CSS or inline SVG).
  - Hide consolidate (🧩) until row hover / focus-within; keep keyboard reachable.
  - Align columns: `[caret-gutter | glyph | number | title+artist | action]` so folders and tracks share the same left gutter.

### 3. Visual hierarchy & theme tokens (`src/styles.css`)

- Replace hardcoded blues/greens with:
  - `--ink`, `--muted`, `--accent`, `--accent-soft`, `--line`, `--surface` / `--chrome`.
- Folder rows: font-weight 600, slightly smaller than current track title size; disc rows uppercase/muted as today but with clearer indent.
- Track title: `--ink` (not link-blue); number: mono + muted; artist: muted, right-aligned or stacked under title on narrow width.
- Selected track: `background: var(--accent-soft)` + `box-shadow: inset 3px 0 0 var(--accent)`.
- Active folder: same treatment, slightly stronger weight.
- Add `[data-theme="dark"]` overrides only where needed (prefer variables so none are required).
- Density: row min-height ~28–32px; reduce vertical padding.

### 4. Empty / loading states inside the list

- When `rows.length === 0` and not loading: short empty hint in the list ("Sin pistas en este root").
- While `loadingMetadata`: keep existing status strip; optionally skeleton shimmer on title placeholders already showing "..." / "Cargando metadatos...".

### 5. Out of scope (this session)

- Flat mode / `TrackTable` revival.
- Drag-and-drop reordering or move-between-folders.
- Virtualization for huge libraries.
- Changing consolidate naming/pattern logic.
- Mobile-specific explorer redesign beyond existing responsive breakpoints.
