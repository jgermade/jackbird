# Deck: a design system of our own

**Date**: 2026-11-03 18:35
**Summary**: Study luu's default theme and propose MP3 Manager's own design system, "Deck", whose
style evokes old portable audio gear (Walkman, Discman, iPod, hi-fi decks).

**Status**: Proposal, awaiting approval. No app code changed yet.

User request (translated): *"Take a look at luu's design system
(`jgermade/luu`, `web/theme/default`). We'll make our own, with a style of its own. It would be
nice if it evoked old audio equipment: Walkman, Discman, iPod, etc."*

Preview: a static page with the tokens, controls and the library in context was built for review
and shared in the session: https://claude.ai/artifact/UKS4Fy59dtkbK4dpZQYWDw (private, not
committed).

## 1. What luu's default theme does

`web/theme/default/` in luu (see its `RECORD/2026-10-21.a-design-system-of-components.completed.md`):

- **A theme is a folder**: `tokens.css` (every value), `components/` (one file each), and a demo
  page that shows them all. A second theme replaces the folder.
- **Tokens by role, not by hue**: grounds (`bg`, `sunken`, `surface`, `field`), inks (`fg`,
  `fg-muted`, `fg-subtle`), four tones (`accent`, `ok`, `warn`, `bad`), each with a `-soft`
  ground. Plus type, space, radii, control heights, shadows and motion.
- **Light on `:root`, dark on `[data-theme="dark"]`**, and any element can be an island of the
  other tone with `data-tone`.
- **Components read tokens with no fallback**: a missing token should look missing, not quietly
  draw a copy of the palette.
- **`prefers-reduced-motion` zeroes the durations once**, in `tokens.css`.
- **App-only tokens live apart** (`luu.css`) from what components need (`tokens.css`).
- **Built beside the app first**; screens move over one at a time.

What we take: the structure and all of the rules above.
What we don't take: the values (palette, type, shape), the jq79 component format (this project is
React), and luu's own surfaces (chat, terminal, context buckets).

## 2. Where mp3-manager stands

- `src/styles.css`: 1718 lines, ~129 top-level classes, 12 colour variables (`--bg`, `--chrome`,
  `--panel`, `--accent`, …) and 56 hard-coded colours outside them. Radii, spacing and type sizes are literals.
- The fonts it names (IBM Plex Sans/Mono, Space Grotesk) are **never loaded**: `index.html` has no
  font link and there is no `@font-face`, so every user gets a system fallback.
- `ThemeService.ts` sets `data-theme` on `<html>`; that stays the switch.
- `index.html` says `lang="es"` and several UI strings are Spanish; both conflict with the
  English-only rule in `AGENTS.md` (see §8).

## 3. Direction

Five rules, which the preview shows:

1. **Evoke, don't copy.** No real product's look: no click wheel, no logos, no chrome photos.
   The references are materials and habits, not a device.
2. **One signal colour.** Signal orange means "this one": the primary key, the selection, a lit
   LED, the playing track. Nothing decorative is orange.
3. **Displays show state.** Now playing, counters and scan progress go in a display window: a
   reflective LCD in the light tone, a VFD in the dark one.
4. **Keys travel.** A pressed key moves 1px down with an inset shadow. Keys sit in banks (a
   recessed well); a latched key stays down with its LED lit.
5. **Printed labels.** Section heads, column heads and field labels are small, wide, uppercase
   and letter-spaced, like the print on a faceplate.

Everything outside those signature elements stays flat and quiet: no textures beyond a faint
brushed line on the faceplate, no skeuomorphic photos.

### Type

| Token | Face | Job |
| --- | --- | --- |
| `--mm-font-sans` | IBM Plex Sans | reading: titles, names, body |
| `--mm-font-label` | Archivo at `font-stretch: 125%`, 600 | printed labels, headings, keys |
| `--mm-font-mono` | IBM Plex Mono | data: paths, durations, track numbers |
| `--mm-font-display` | Doto, 700 | dot-matrix display: counters, track/total |

Sizes: `--mm-text-label` 10px, `-sm` 12px, `-md` 13px, `-lg` 15px, `-xl` 20px, `-2xl` 28px.
`--mm-tracking-label: .14em`.

### Shape, space and motion

- Space: `--mm-space-1` … `-8` = `.25rem .5rem .75rem 1rem 1.25rem 1.5rem 2rem 3rem`.
- Radii: `--mm-radius-key` 3px, `-md` 6px, `-lg` 14px, `-full` 999px.
- Controls: `--mm-control-sm` / `-md` / `-lg` = 24 / 30 / 36px.
- Shadows: `--mm-key-shadow`, `--mm-key-pressed`, `--mm-well-shadow`, `--mm-shadow-md`, per tone.
- Motion: `--mm-ease: cubic-bezier(.2, .8, .2, 1)`, `--mm-duration-key` 70ms,
  `--mm-duration` 180ms; both `0ms` under `prefers-reduced-motion: reduce`.

## 5. Components

React, store-free, styled only with `--mm-*` tokens (no fallbacks). Classes are prefixed `mm-`:
the preview hit a collision between an LED dot (`.led`) and a meter variant (`.meter.led`), and a
prefix per component avoids that class of bug.

| Component | Replaces / used by |
| --- | --- |
| `Key` (primary, secondary, ghost, danger; sm/md/lg; square) | every button: `.playback-icon`, `.preferences-trigger`, modal actions, `DetailActionBar` |
| `KeyBank` + latching `Key` with LED | transport in `PlaybackBar`; flat/wizard toggle; future shuffle/repeat |
| `SlideSwitch` (hold switch) | `ThemeToggle`; boolean preferences |
| `Display` + `Counter` | now playing in `PlaybackBar`; scan progress |
| `Meter` (in a display, or as LEDs on the chassis) | the "loading metadata X/Y" text |
| `Lamp` | track and file states, sync status |
| `Reel` (cassette hub spinner) | busy states: scanning, writing |
| `Field`, `TextInput`, `Select`, `Checkbox` | `MetadataEditor`, `PreferencesModal`, the library filter |
| `Tabs` (stripes on the active tab) | `RootTabs` |
| `Panel` (chassis head) and `Modal` | `MetadataEditModal`, `TrackInfoModal`, `PreferencesModal` |
| `ListRow`, `Table` | `TrackWizardList`, `AlbumOverview` |
| `Stripes` | brand mark, active tab, placeholder cover art |

## 6. Layout in the repo

```
src/theme/deck/
  tokens.css          every --mm-* value, Silver on :root, Graphite on [data-theme="dark"]
  fonts.ts            imports the self-hosted faces
  components/
    Key.tsx           one component per file, each with its own Key.css (classes prefixed mm-)
    ...
theme/index.html      demo page, served at /theme/ (second Vite entry in vite.config.ts)
```

Fonts are self-hosted through Fontsource so the app keeps working offline and makes no request
to a third party: `@fontsource/ibm-plex-sans`, `@fontsource/ibm-plex-mono`,
`@fontsource-variable/archivo`, `@fontsource-variable/doto` (four new dependencies).

## 7. Plan

1. **Beside the app**: `tokens.css`, fonts, the components in §5, and the demo page at `/theme/`.
   Nothing in the app changes.
2. **Faceplate**: top bar, `PlaybackBar` (transport + display window), `RootTabs`, `ThemeToggle`.
3. **Library**: `TrackWizardList`, `AlbumOverview`, `DetailActionBar`, scan progress.
4. **Modals and forms**: `MetadataEditModal`, `MetadataEditor`, `TrackInfoModal`,
   `PreferencesModal`.
5. **Clean-up**: remove the old variables and the hard-coded colours from `styles.css`.

Each step is appended here as an extension with its walkthrough and validated with
`npm run build`.

## 8. Cost, rejected options, open questions

**Cost**: four font dependencies (~100–200 KB of woff2, latin subsets only), one extra Vite entry,
and a gradual rewrite of `styles.css` (steps 2–5).

**Rejected**:

- *Skeuomorphic realism* (photo textures, brushed-metal images, 3D knobs): heavy, ages badly and
  costs legibility. Five signature elements carry the style instead.
- *Re-skinning luu's `tokens.css`*: the user asked for a style of our own. We keep its structure
  and none of its values.
- *Porting luu's components*: they are jq79; this app is React.
- *Replicating a specific device* (click wheel, a Walkman's faceplate): it would be a copy, not a
  style.
- *Google Fonts at runtime*: no dependency, but it needs the network and calls a third party from
  a local-first app.

**Open questions for the user**:

1. Name: `deck` (`src/theme/deck/`), or `default` as in luu?
2. Fonts: self-host with Fontsource (four dependencies) or link Google Fonts?
3. Light chassis: silver as proposed, or a dark chassis in both tones, as luu does with its bars?
4. The English-only rule: translate the Spanish UI strings and `lang="es"` as part of this work,
   or in a separate record?
5. Once approved, write the plan in §7 as a Gantt chart under `ROADMAP/2026-11-03/`?

## Extension — 2026-11-03 18:42 — Decisions, revised plan and phase 1 detail

### Decisions (user, translated)

1. **Folder**: `/theme/default/`, as in luu. The theme sits at the front-end root, next to
   `index.html`, the way luu's sits in `web/`, and its demo is served at `/theme/default/`. This
   replaces `src/theme/deck/` in §6. "Deck" stays the name of the style, not of the folder.
2. **Fonts**: download them. The woff2 files (latin subset, which covers English and Spanish) are
   committed to `theme/default/fonts/` with their OFL licences. No Fontsource dependency and no
   request to a third party at runtime. This replaces the four dependencies in §6.
3. **Tones**: Silver is the light tone and Graphite the dark one, as proposed.
4. **Languages**: the UI has English and Spanish texts, with English as the fallback. This needs an
   i18n layer, and the English-only rule in `AGENTS.md` needs an exception for translation files
   (updated in the same commit). It becomes its own step, before any screen moves over, so every
   migrated screen takes its strings from it.
5. **Roadmap**: `ROADMAP/2026-11-03/deck-design-system.md`.

### Revised plan (supersedes the order in §7)

1. Theme beside the app: tokens, fonts, components, demo at `/theme/default/`.
2. i18n: English and Spanish, English fallback; the language follows the browser and can be
   chosen in Preferences.
3. Faceplate: top bar, `PlaybackBar`, `RootTabs`, `ThemeToggle`.
4. Library: `TrackWizardList`, `AlbumOverview`, `DetailActionBar`, scan progress.
5. Modals and forms: `MetadataEditModal`, `MetadataEditor`, `TrackInfoModal`, `PreferencesModal`.
6. Clean-up: remove the old variables and hard-coded colours from `styles.css`.

### Phase 1 detail

```
theme/default/
  index.html          demo document; sets data-theme before the first paint
  demo.tsx, demo.css  the demo: tokens read back from computed style, every component and state
  tokens.css          §4 values: Silver on :root and [data-tone="light"],
                      Graphite on :root[data-theme="dark"] and [data-tone="dark"]
  fonts.css           @font-face for the four families
  fonts/              *.woff2 + OFL-*.txt
  components/         one .tsx + one .css per component, classes prefixed mm-, index.ts barrel
```

- Dark is selected by `data-theme` only, with no `prefers-color-scheme` block: `ThemeService`
  already resolves the system preference and always sets the attribute.
- Components: `Key`, `Led`, `KeyBank`, `KeySelect` (a bank with one key down), `SlideSwitch`,
  `Display` (+ `DisplayRow`, `DisplayLabel`, `DisplayTitle`, `Counter`), `Meter`, `Lamp`, `Reel`,
  `EqBars`, `Legend` (printed label), `Field`, `TextInput`, `Select`, `Checkbox`, `Tabs`, `Panel`,
  `Modal` (native `<dialog>`, like the current modals), `Stripes`, `ListRow`, `Table`.
- Components take their texts as props or children and hold none of their own, except
  accessible names a caller can override, so i18n (step 2) does not reach into the theme.
- `vite.config.ts` gets a second entry (`theme/default/index.html`); `tsconfig.json` includes
  `theme`.
- Nothing under `src/` changes.
- Validation: `npm run build`, and a look at the demo in both tones at desktop and phone width.
